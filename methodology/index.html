How the database is built.

Infinite Sauna is designed to make specifications easier to compare without pretending every field is equally available or equally reliable.

Data methodology

How Infinite Sauna verifies specifications and prices

Infinite Sauna is a normalized sauna-model database. The goal is not to fill every cell at any cost; it is to attach a specification only when a source can be matched to the correct model or configuration.

Primary catalog and featured retailer

InHouse Wellness remains the featured retail source where it sells a model. Its catalog supplies product identity, brand, current listed price, reference price when exposed, model/SKU, image and product URL.

Commercial disclosure: InHouse Wellness is intentionally featured where available. Infinite Sauna also captures prices from selected retailers and manufacturer-direct catalogs so users can compare the same model across sellers. A retailer appearing in the database is not an endorsement.

Manufacturer and model-specific verification

data/manufacturer_sources.csv is the controlled source registry for technical specifications. Rows may contain explicit, model-specific values when a page contains multiple heater packages or configurations that would make generic text extraction ambiguous. Explicit source-backed values fill missing fields only; they do not overwrite a populated value.

Manufacturer pages are preferred for product identity, dimensions, materials, weight, warranty and electrical requirements. Detailed authorized-retailer pages can be used as a cross-check where the manufacturer page does not expose a field in machine-readable text.

Retailer price sources

data/retailer_sources.csv contains direct product URLs for important exact-model checks. data/retailer_catalogs.csv contains selected catalog feeds used to discover additional offers and, when explicitly allowed, models that InHouse Wellness does not carry.

Each captured offer records the retailer, product URL, current source price, reference price when available, source type and check date. Prices can change at any time and may reflect different heater packages, wood choices, accessories, shipping terms or promotions.

Model matching

The updater prefers exact normalized SKUs/model numbers. Known formatting differences such as spaces, hyphens and a small set of material/edition suffixes can be normalized, but the script prefers exact matches before fuzzy suffix matching. New external-only products are added only from source rows/catalogs configured to allow new models.

Fields we normalize

The schema supports brand, model, title, price, reference price, sauna type, placement, capacity, voltage, amperage, plug type, EMF terminology, infrared spectrum, red-light integration, infrared wattage, traditional heater, heater output, maximum temperature, exterior dimensions, interior dimensions, wood/materials, product weight and warranty.

What “Not verified” means

It means the current source set did not expose that field in a form the parser or explicit registry could attach reliably to that exact model. It does not mean the sauna lacks the feature.

Update frequency

A GitHub Actions workflow refreshes the database weekly and can be run manually. After a successful refresh it regenerates the JSON/CSV dataset, homepage, model pages, brand pages, comparison pages and XML sitemap.

Corrections and installation-critical details

Specifications and packages change. Before purchase or installation, verify voltage, amperage, breaker/receptacle requirements, heater clearances, outdoor siting, dimensions and included heater/controller against the current manufacturer documentation and the exact seller configuration.
